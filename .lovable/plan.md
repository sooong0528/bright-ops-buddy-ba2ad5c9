# 智能运维 Demo 需求变化落地方案

## 一、需求变化对照（与当前实现的 Diff）

### 1. 新增模块

- **资产管理**（一级模块）：主机 / 数据库 / 应用服务 / 中间件 4 类；含"观测配置"入口（Zabbix Host/Item 映射、日志观测项、巡检阈值）。
- **故障分析**（一级模块）：独立于巡检，由用户从异常/关注记录**手动发起**；包含指标回溯、日志辅助、知识匹配、原因假设、处置建议、人工确认。

### 2. 数据源扩展

- 除 Zabbix（CPU/内存/磁盘/Ping）外，新增 **Filebeat + ES 日志**（服务状态、错误日志数量、日志片段），并新增"服务状态"指标类别。

### 3. 模块级调整


| 模块    | 当前                   | 调整后                                                                    |
| ----- | -------------------- | ---------------------------------------------------------------------- |
| 巡检中心  | 只看结果                 | 新增"手动发起故障分析"、"带上下文追问"入口；异常/关注项支持跳转分析                                   |
| 巡检管理  | 任务 + 判定规则            | 保留；判定规则补充"服务状态 / 日志关键字"类型；名称调整为"巡检配置管理"                                |
| 智能问答  | 4 类（知识/数据/报告生成/报告追问） | 改为 **3 类**：知识库问答、系统数据查询、上下文追问（报告/异常/关注）。**去掉"报告生成"作为问答类型**；报告生成由报告中心触发 |
| 报告中心  | 巡检质量 / 风险研判 / 知识服务   | 改为 **巡检报告 / 故障分析报告 / 知识服务情况分析报告**（替换"风险研判"为"故障分析报告"）                   |
| 总览驾驶舱 | 态势 + 趋势 + 健康分布       | 新增"待关注事项"、"Agent 工作情况"卡片                                               |
| 知识库管理 | 基础 CRUD              | 新增知识引用统计、知识盲区清单                                                        |
| 用户权限  | 4+ 角色                | 简化为 2 类：系统管理员 / 运维人员                                                   |
| 审计留痕  | 用户 + 任务              | 新增 Agent 调用链、数据来源审计                                                    |


## 二、目标信息架构

```text
运维工作台
├─ 总览驾驶舱          巡检概览 / 异常关注 / 待关注 / Agent 情况 / 最新报告
├─ 巡检中心            日/周/月结果 · 异常追踪 · [手动发起故障分析] · [上下文追问]
├─ 故障分析            [新] 异常/关注列表 → 详情（指标回溯+日志+知识+假设+建议）
├─ 智能问答            知识库 / 系统数据 / 上下文追问
└─ 报告中心            巡检 / 故障分析 / 知识服务

配置与管理
├─ 资产管理            [新] 4 类资产 + 观测配置（Zabbix/日志）
├─ 巡检配置        任务 + 判定规则
├─ 知识库管理          文档 + 引用统计 + 知识盲区
├─ 用户与权限          3 角色
└─ 审计留痕            用户/任务/Agent/数据来源
```

## 三、分阶段实施

### 阶段 A：模块骨架与导航（1 步）

- `App.tsx` 增路由：`/assets`、`/analysis`（故障分析）
- `AppSidebar.tsx`：主区加"故障分析"；管理区加"资产管理"（置顶）；"巡检管理"改名"巡检配置管理"
- `AppLayout` titleMap 同步

### 阶段 B：Mock 数据扩容 `src/lib/mockData.ts`

- `assets`：主机/DB/应用/中间件各若干条 + 通用字段 + 类型专有字段
- `observationConfigs`：资产→Zabbix Host/Item/日志观测项映射
- `abnormalRecords`：巡检异常/关注记录池（含证据快照、等级、来源任务）
- `analysisTasks`：故障分析任务（关联异常记录、指标回溯、日志片段、知识引用、原因假设、处置建议、人工确认事项、状态）
- `logSnippets`：ES 日志片段样本
- `agentRuns`：Agent 调用链样本（供审计和驾驶舱）

### 阶段 C：资产管理 `src/pages/Assets.tsx`（+ 组件）

- 列表：资产名称/类型/业务系统/IP:端口/环境/状态/重要级别/责任人/观测状态
- 新增/编辑抽屉：通用字段 + 类型切换后展示专有字段
- 资产详情抽屉：档案 / 关联巡检结果 / 异常记录 / 知识条目 / 观测配置
- 观测配置子抽屉：Zabbix Host 映射、Item 多选、阈值维护（关注/异常 + 判断窗口）、日志观测项（源/路径/关键字/窗口）
- "AI 自动识别关联"按钮（复用已有 edge function 模式，Demo 直接 Mock）

### 阶段 D：故障分析 `src/pages/Analysis.tsx`

- 左：异常/关注记录列表（来源 = 巡检结果），可筛选状态/等级/资产
- 右：分析任务详情
  - 分析对象与资产上下文
  - 指标趋势回溯（recharts，异常前后窗口）
  - 日志辅助排查（命中片段 + 关键字高亮）
  - 知识库匹配（引用卡片，带来源）
  - **原因假设 · 处置建议 · 人工确认事项**（分区展示）
  - 操作：生成故障分析报告、标记完成、追问
- 入口：巡检中心异常项 → "发起分析"；本页也支持从列表手动发起

### 阶段 E：巡检中心 `Inspection.tsx` 调整

- 每个异常/关注项增加两个操作：`发起故障分析`（跳 `/analysis?record=<id>`）、`追问`（跳 `/assistant`，携带上下文进入"上下文追问"模式）
- 巡检指标类别新增"服务状态"（Mock）
- `RunDetailSheet` 中的告警项同样支持这两个入口

### 阶段 F：智能问答 `Assistant.tsx` 重构类别

- 三类：`knowledge` / `data` / `context`（合并原"报告追问"+"异常追问"）
- 去掉"报告生成"入口（改为报告中心手动/定时生成）
- context 模式支持来源标签：报告 / 巡检异常 / 关注项
- sessionStorage key 统一为 `assistant.context`，包含 `{sourceType, sourceId, title, snapshot}`

### 阶段 G：报告中心 `Reports.tsx` 分类替换

- 三类报告：`inspection` / `analysis` / `knowledge_service`
- 卡片和详情内容按新字段模板重构：
  - 巡检报告：任务执行情况、正常/关注/异常统计、异常明细、处置建议
  - 故障分析报告：异常记录、影响对象、指标回溯、日志、知识引用、原因假设、处置建议、人工确认、证据链
  - 知识服务报告：问答总数、命中率、热门问题 Top5、高频文档、知识盲区
- 保留：导出、追问（现在跳 context 模式）、标记重要、归档、备注

### 阶段 H：总览 / 知识库 / 审计 / 权限 小改

- Dashboard 增加"待关注事项"、"Agent 工作情况"两块卡片
- Knowledge 增加"引用次数"列 + "知识盲区"Tab
- Audit 类型枚举增加 "Agent 调用"、"数据来源"
- Users 角色下拉限定为 2 类

## 四、技术要点

- 全部 Mock，无需新增后端表；`inspection-ai` edge function 保留
- 新增 shadcn 组件按需引入，不引入新依赖
- 遵守现有设计系统 token（青蓝主题、12px 最小字号、隔行表格）
